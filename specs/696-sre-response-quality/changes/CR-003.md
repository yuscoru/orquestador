# CR-003 — Show Quality Evolution in a lateral modal drawer

status: CLOSED
origin: ISS-005
requested: 2026-10-20 by user

## Motive

The implemented `/quality` page renders the selected target's Evolution card inline below the catalog. The user wants to keep the catalog in place and show the same Evolution content in a right-side overlay, following the established Playbook edit drawer presentation. This is a presentation change only: it does not open or edit Playbooks.

## Delta

### D1 — Evolution moves from inline content to an overlay

Previous: selecting a catalog row renders the Evolution card as a sibling below the catalog in the page flow.

New: selecting a catalog row opens a right-side, full-height modal drawer over the catalog. The drawer contains the existing target title/description, loading state, 403/404/409/unexpected-error states, empty state, `QualityEvolutionChart`, and `QualityPointsTable`. No duplicate inline Evolution block remains below the catalog.

### D2 — Reuse the Dialog/drawer pattern, not the Playbook editor

Use the shared Radix/shadcn primitives from `src/components/ui/dialog.tsx` and the right-side overlay presentation demonstrated by `PlaybookEditorDrawer`. Do not reuse `PlaybookEditorDrawer` itself because its API and body are coupled to Playbook forms, save/dirty state, skills, tags and prompt audit.

The Evolution drawer has correct `DialogTitle`/`DialogDescription`, focus trapping/restoration, Escape and outside-click close behaviour supplied by Radix, vertical scrolling, and horizontal overflow containment for the points table. It remains usable at narrow viewports.

### D3 — Selection and close behaviour

Selecting any catalog row sets that target as selected and opens the drawer. Selecting another row replaces the target. Closing with the close control, Escape, or outside click closes the drawer and clears the current selection, so no row remains highlighted as an open detail. There is no URL/deep-link state.

### D4 — Data behaviour is unchanged

The existing React Query history request, cache behaviour, endpoint, types, metric descriptors and all rendering semantics remain unchanged. The query is still enabled only for an authorized, hydrated user with a selected target. Closing may leave normal React Query cache entries, but no Evolution UI stays visible.

No API, Agentics, persistence, RBAC or contract change is required.
