# CR-001 — Quality history: metric-scored points only, last-5 per target, all-targets history endpoint, type-less history URL

status: APPROVED
origin: ISS-001, ISS-002, ISS-003 (user decision overriding triage recommendation on ISS-003)
requested: 2026-10-19 by user (admiral session)

## Motive

User review of the implemented quality-read contract found that: (1) the valid-point predicate
hides historical evaluations the user wants to see; (2) no route returns, for all targets at once,
the per-date history of the two metrics (rubrics, hallucinations); (3) the `{target_type}` path
parameter in the history URL is unwanted — the user states an agent and a playbook never share a
name, and assumes that uniqueness for the contract even though the schema does not guarantee it
(ISS-003 triage evidence; risk accepted by the user, mitigated by D3's collision guard).

## Delta

### D1 — Valid-point predicate redefined (ISS-001)

Previous: schema_version 4; mode offline_log; checkpoint_committed true; status in the five
contract statuses; rescore absent/null; validation absent/null.

New: a document is a series point iff **all** hold: `schema_version` 4; `mode` `offline_log`;
**both** headline metrics carry a score (rubrics and hallucinations values present, not
null/unavailable). The committed/status/rescore/validation conditions are dropped. The predicate
remains defined once and used by all quality queries (catalog, history, all-targets history,
detail, cases), preserving the single-predicate invariant and total==Σ coherence. Spec C3's
observable outcome (no judge_unavailable points) is preserved de facto: such points carry no
metric scores.

### D2 — History is the last 5 scored points, descending (ISS-001)

Previous R2: paginated full history (`limit` 1–200 default 50, `offset`, `order`).

New R2: returns at most the **last 5** points by evaluation timestamp **descending**
(tie-break `eval_run_id`), no paging parameters. A target with zero scored points → 404.
SC-001 ("complete valid history by following pages") is amended accordingly.

### D3 — History URL loses {target_type} (ISS-003, user decision)

Previous: `GET /quality/targets/{target_type}/{target}/evaluations`.
New: `GET /quality/targets/{target}/evaluations`. The query filters by `target` only. Defensive
guard: if matching documents span more than one `target_type`, the route answers 409 (Spanish
detail) instead of mixing series — making the uniqueness assumption observable, never silent.
FR-002's identity pair stays for persistence and for catalog items; it no longer appears in the
history path. Catalog R1 keeps `target_type` in items and as optional query filter (unchanged).

### D4 — New route R6: all-targets history (ISS-002)

`GET /quality/targets/history` — paginated **by targets** (`limit`/`offset` over targets,
documented default and hard maximum, deterministic order by `(target_type, target)`). No
`target_type` or `eval_profile` filters. Each item: `{target_type, target, eval_profile,
history: [EvaluationPoint x up-to-5]}` with the same point shape as R2, last 5 by date
descending, same predicate. Reuses the existing full-series fetch
(`list_quality_catalog_points`); reduction changes from latest-1 to latest-5.
