# CR-002 — EvaluationPoint.status nullable for legacy points without monitoring block

status: APPROVED
origin: ISS-004 (SPEC_DEFECT found validating CR-001 on real dev data)
requested: 2026-10-19 by api-engineer blocker 696-api-17; decision owner: user

## Motive

CR-001 exposes all scored history points (v4 + offline_log + both metrics scored). Real dev data
contains scored points written before the writer added the `monitoring` block: 72/80 matching
documents have no `monitoring.status`. The point model requires a status among five literals, so
every route that serializes such a point returns 500. The CR-001 assumption ("no valid status =>
no scores") is disproven by the data.

## Delta

### D1 — status becomes nullable in the point shape

Previous (plan.md §3 point shape, FR-005/FR-007 semantics): every history point carries a
measurement status, machine-readable, one of the five evaluator states.

New: `status` is `Optional[Literal[measured, low_sample, no_activity, no_eligible_cases,
evidence_incomplete]]`, `null` when the persisted document has no `monitoring.status` (legacy
writer output). No value is invented. `sample_sufficient` and `judge_model` remain optional as
already modeled. Consumers MUST treat `status: null` as "status unknown (legacy point)".
Additive OpenAPI schema change; applies to every route that returns points (R2, R6, catalog
latest, detail).

No other CR-001 semantics change: predicate, last-5, type-less URL, 409 guard and R6 stay as
approved.
