# ISS-007 — Quality API rejects persisted `judge_unavailable` evaluations

status: CR_APPROVED_AWAITING_IMPLEMENTATION
reported: 2026-10-22 by post-concurrency verification
repositories: soarplus-api (consumer), soarplus-agentics (schema provider)
touches_contract_or_spec: yes
triage: required

## Observation

Two completed and persisted evaluations have monitoring status `judge_unavailable` after one hallucinations judge score was unavailable. Agentics read-only evidence confirms both documents exist, accounting completed and checkpoint correctly remained false.

Independent requests to the audited local Quality API:

- measured run `10f2139e8f9948f09b8b82c21c35cbb5` returns 200 with exact metrics;
- `3b3b92485eb04087aa8541eadd2b3302` and `da7397152061483fb881a554847abafc` return 500.

The API log reports Pydantic validation failure on `QualityEvaluationPoint.status`: allowed values are `measured`, `low_sample`, `no_activity`, `no_eligible_cases`, `evidence_incomplete`; input `judge_unavailable` is rejected. Thus the frontend cannot display these two legitimate persisted results.

No payload, prompt or credential was inspected. No code or DB mutation occurred.

## Expected

C-03's agent_eval_results writer schema is authoritative for persisted statuses and C-01 must safely project all supported writer statuses (or deliberately map them under an approved compatibility rule) without a 500. The exact intended response enum/UI behavior requires triage against approved spec/contracts and current repository evidence.

## Triage

outcome: SPEC_DEFECT

Evidence:

- Agentics writer explicitly persists `judge_unavailable` and tests that it prevents checkpoint commit; operational documentation includes it as a supported outcome.
- API filters intentionally admit v4/offline_log points with both numeric headline metrics regardless of status, then pass monitoring status through literally.
- API DTO, OpenAPI and tests intentionally permit exactly five non-null statuses and reject `judge_unavailable`.
- The approved API spec/plan themselves fix that five-value enum under an observational premise that no `judge_unavailable` points existed. ISS-007 disproves that premise with two legitimate persisted points.

Although the observable 500 is an API consumer defect, the implementation matches the approved five-value spec and tests. Under the change protocol this is therefore primarily `SPEC_DEFECT`, not a direct FIX: correcting it changes the approved response enum/OpenAPI.

## Routing

CR-004 revised and delta-approved by the user on 2026-10-22: replace the closed enum with `string|null`; preserve all known and future writer strings in R1/R2/R3/R6; keep null exclusively legacy; map malformed non-string status metadata to fixed API sentinel `invalid_status` with structured type-only logging and no raw value. API/OpenAPI/controller regressions span R1/R2/R3/R6; R4/R5 remain unchanged. Frontend uses known branches plus a generic degraded default and distinct invalid sentinel, never measured/green/zero. The complete response remains available.

Do not alter persisted documents or loosen validation ad hoc. No ADO item created or authorized.

## Provider semantics confirmed

At agentics commit `5e720a3`, one case with judge `score=None` is enough to make the whole monitoring
status `judge_unavailable`. Available case scores are still aggregated, so the point can carry
numeric metric values and `sample_sufficient=true`. Priority is judge unavailable over evidence
incomplete and other measurement states. The document persists but checkpoint remains false; the
next delta window starts from the prior committed checkpoint. A propagated exception becomes
`execution_error`, while no-score/parser/model outcomes become judge unavailable; no-usage alone
does not select the state. The two observed runs each had exactly 1/5 hallucinations cases without a
judge score, 25/25 calls completed, no LLM failure/without-usage, partial numeric metrics, persisted
result and no checkpoint advance. The underlying reason for score=None is not persisted, so timeout
internal/parser/non-scorable response cannot be distinguished and must not be inferred.
