# ISS-003 — Redundant {target_type} path parameter in the history endpoint

status: SUPERSEDED_BY_CR
reported: 2026-10-19 by user (admiral session)
repository: soarplus-api
touches_contract_or_spec: yes
triage: done (2026-10-19, api analyst, 696-api-11)

## Observation

`GET /quality/targets/{target_type}/{target}/evaluations` (plan.md §3 R2) takes both
`target_type` and `target` in the path. The user observes that a target has exactly one type,
so `{target_type}` is redundant and the URL could be `/quality/targets/{target}/evaluations`.

To verify in triage: is a target name actually unique **across** types in the persisted data
(agent_eval_results v4), or can an agent and a playbook share a name? The answer decides
whether the parameter is redundant or a necessary disambiguator. Depending on the outcome,
the remaining /quality routes should be reviewed for the same pattern.

## Triage

outcome: NOT_A_DEFECT
evidence: >
  api analyst, ANSWER 696-api-11 on HEAD d8faac3. The identity key across the whole design is the
  PAIR (target_type, target), not target alone: the writer (soarplus-agentics) defines the
  compound index ix_target_ts on (target_type, target, timestamp)
  (tools/sre-response-quality/sre_eval/writer.py:25) and queries by both; the API history query
  filters by both as equality literals (documentdb.py:1129-1132, count 1147-1150); the catalog
  groups by key=(target_type,target) (control_quality.py). Nothing in the schema or writer
  guarantees name uniqueness ACROSS types: agents and playbooks come from different namespaces
  with free names, so collisions are possible (actual collisions in live data NOT VERIFIABLE
  without dev DocumentDB; owner user/ops). Removing {target_type} would mix both types on a
  collision, assume uniqueness nobody guarantees, lose enum validation and use the compound index
  worse. Only other /quality use of target_type is an optional query filter on R1; R3/R4 key on
  globally-unique eval_run_id. Recommendation: keep the parameter. A URL change would be a CR on
  C-01 with ambiguity risk.

## Routing

CR-001 (user decision 2026-10-19, overriding the triage recommendation): the user asserts an
agent and a playbook never share a name and wants the type-less URL. Folded into CR-001 delta D3
with a 409 collision guard so the assumption is observable. Live-data collision check remains a
user/ops item.
